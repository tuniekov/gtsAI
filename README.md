# gtsAI

Шлюз ИИ для gtsERP: чат, который читает данные системы, предлагает правки и
применяет их с подтверждением и откатом.

Подробности устройства — в [CLAUDE.md](CLAUDE.md).

## Где открывается

| Место | Что это |
|---|---|
| Сайт → Администратор → **Чат ИИ** | рабочая страница, ставится пакетом на оба сайта (`_build/configs/resources.js`) |
| Менеджер MODX → Компоненты → **ИИ (gtsAI)** | подключения, настройки чатов, история и лог вызовов |
| Страница расчёта → левое меню → **Чат ИИ** | чат с контекстом открытого расчёта |

## Доступ к базе только на чтение

Чат умеет отвечать на вопросы, которых не достать через таблицы, — сводные
цифры, группировки. Для этого есть инструмент `sql_query`, и он ходит в базу
**отдельным пользователем MySQL, у которого есть только SELECT**.

Почему именно так, а не фильтром по словам в запросе: фильтр обходится —
точкой с запятой, комментарием, `SELECT … INTO OUTFILE`. Права пользователя
обойти нельзя. Проверки в коде (один запрос, только SELECT/SHOW/EXPLAIN,
обязательный LIMIT, чёрный список таблиц) эту защиту дополняют, а не заменяют.

### 1. Завести пользователя

Выполнить от администратора MySQL. Пароль — свой, не из примера.

```sql
-- Пользователь только для чтения из чата ИИ.
-- Хост 'localhost' — если сайт и база на одной машине; иначе укажите адрес
-- веб-сервера вместо localhost (или '%' при доступе откуда угодно).
CREATE USER 'gtsai_ro'@'localhost' IDENTIFIED BY 'ЗАМЕНИТЕ_ПАРОЛЬ';

-- Право ровно одно и на одну базу. GRANT ALL, CREATE, DROP и прочее
-- не нужны ни в каком виде.
GRANT SELECT ON `modx28`.* TO 'gtsai_ro'@'localhost';

-- FILE не выдаём никогда: с ним SELECT умеет писать файлы на диск сервера
-- (INTO OUTFILE) и читать их (LOAD_FILE).
-- Ограничим и нагрузку: больше 200 запросов в час одному чату незачем.
ALTER USER 'gtsai_ro'@'localhost' WITH MAX_QUERIES_PER_HOUR 200;

FLUSH PRIVILEGES;
```

Для второго сайта то же самое со своей базой:

```sql
CREATE USER 'gtsai_ro'@'localhost' IDENTIFIED BY 'ЗАМЕНИТЕ_ПАРОЛЬ';
GRANT SELECT ON `kdaitx_vk24`.* TO 'gtsai_ro'@'localhost';
ALTER USER 'gtsai_ro'@'localhost' WITH MAX_QUERIES_PER_HOUR 200;
FLUSH PRIVILEGES;
```

Проверить, что прав ровно столько, сколько задумано:

```sql
SHOW GRANTS FOR 'gtsai_ro'@'localhost';
-- Ожидаем две строки: USAGE ON *.* и SELECT ON `база`.*
-- Если видите что-то ещё — лишнее надо отозвать:
-- REVOKE INSERT, UPDATE, DELETE ON `база`.* FROM 'gtsai_ro'@'localhost';
```

Убедиться, что запись действительно невозможна (должно вернуть ошибку доступа):

```sql
-- выполнять ПОД gtsai_ro
UPDATE modx_site_content SET pagetitle = pagetitle LIMIT 1;
```

### 2. Прописать в настройках MODX

⚠️ **Хост берите из `core/config/config.inc.php` этой же установки** (`$database_dsn`),
а не пишите `localhost` по привычке. На OSPanel сайт ходит в базу по имени модуля —
`mysql:host=mysql-5.7;…`; `localhost` там упирается в сокет, которого нет, а
`127.0.0.1` — в закрытый порт. Пользователя заводите под тот же хост: с именем
модуля MySQL видит обычное TCP-подключение, и `'gtsai_ro'@'localhost'` ему не подходит.

| Настройка | Значение |
|---|---|
| `gtsai_sql_dsn` | тот же, что `$database_dsn` сайта, например `mysql:host=mysql-5.7;dbname=modx28;charset=utf8mb4` |
| `gtsai_sql_user` | `gtsai_ro` |
| `gtsai_sql_password` | пароль пользователя |
| `gtsai_sql_deny` | таблицы, которые не показывать даже на чтение (по умолчанию `modx_users,modx_user_attributes,gtsapi_tokens`) |

Пока `gtsai_sql_dsn` пуст, инструмент SQL модели не выдаётся вовсе — даже если
он включён в настройке чата.

Пароль переживает сборку пакета: в `_build/config.js` стоит `update.settings: false`.
Менять на `true` нельзя — установка вернёт всем настройкам значения из конфига,
то есть сотрёт пароль и адрес соединения. Новые настройки при `false` всё равно
создаются, не трогаются только уже заполненные.

## Подключение к провайдеру

Подключение `neiro-api` (протокол Anthropic, `https://neiro-api.ru`) пакет везёт
с собой и на пустой установке создаёт первым — чаты ссылаются на него через
`conn_id = 1`. **Ключа в пакете нет и быть не может:** строки данных находятся
по имени и перезаписываются при каждой установке, так что пустой ключ в пакете
стирал бы вписанный на площадке.

Ключ вписывают один раз: **Компоненты → ИИ (gtsAI) → Подключения**. Пока он
пуст, чат так и отвечает — куда идти, вместо запроса к провайдеру впустую.

## Какие чаты везёт пакет

| Чат | Откуда приезжает | Что умеет |
|---|---|---|
| `default` | gtsAI, одинаков везде | чтение таблиц; ничего не знает про конкретную систему — пакет ставится и туда, где gtsERP нет |
| `admin` | gtsAI, **свой текст на каждом сайте** (`_build/configs/data.js`, блоки `modx28` и `vk24`) | чтение + SQL; в промпте перечислены таблицы этой площадки, чтобы не искать их каждый раз |
| `raschet` | **gsRaschet**, а не gtsAI | правка строк расчёта с подтверждением; где расчётов нет, настройки тоже нет |

⚠️ Строки находятся по `name` и перезаписываются при каждой установке пакета.
Правку промпта вносить в `data.js` того пакета, который этот чат везёт, а не
в админке — иначе она исчезнет на следующей установке.

### 3. Включить в нужном чате

В менеджере: **Компоненты → ИИ (gtsAI) → Настройки чатов** → у нужной записи
поставить «Доступ к SQL (только чтение)».

### Что проверено

| Запрос из чата | Чем кончается |
|---|---|
| `SELECT …` | выполняется; без `LIMIT` дописывается свой (по умолчанию 50, максимум 200) |
| `SELECT 1; DROP TABLE …` | «Только один запрос без точки с запятой» |
| `UPDATE …`, `DELETE …`, `CREATE …` | отбивает проверка, а под ней — база: `1142 command denied` |
| `SELECT … FROM modx_users` | «К таблице modx_users обращаться нельзя» (список `gtsai_sql_deny`) |
| `SELECT … INTO OUTFILE` | «запрещённая конструкция»; `LOAD_FILE()` вернул бы NULL — права FILE нет |
| `SHOW TABLES`, `DESCRIBE` | выполняются (им `LIMIT` не дописывается — они его не принимают) |

⚠️ У инструментов таблиц права пользователя работают, у SQL — нет: запрос
видит всё, что видит пользователь базы. Поэтому включать его стоит там, где
чат и так для администраторов, а чувствительные таблицы держать в `gtsai_sql_deny`.
